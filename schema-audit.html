High severity
Model · FieldTypeIssue
user
refreshTokens		 security Missing select: false. Live bearer tokens are returned by every User.find() / User.findOne() that doesn't explicitly project them out. toJSON() strips them but toObject() does not — any middleware or logging path that calls .toObject() leaks raw refresh tokens.
user
loginAttempts & lockedUntil		 security Missing select: false. Returned in all queries. An attacker who can read any user document knows exactly how many remaining attempts remain before lockout.
user
passwordResetOtpExpires		 security passwordResetOtpHash has select: false but passwordResetOtpExpires does not. Expiry date leaks whether a reset is in-flight and how long the window is, reducing brute-force difficulty.
owner
taxId		 security Stores GSTIN/PAN (per code comments). Missing select: false — sensitive PII is returned in every owner query by default. Also missing maxlength.
listing
type		 correctness Required field with no enum constraint: type: { type: String, required: true }. The codebase treats this as 'sale' | 'rent' but any string is accepted. All listing-type filters and BuyerRequirement.matchesProperty() silently match against arbitrary values.
activityLog
entityType		 correctness enum: ['client', 'task'] only. The transaction controller logs with entityType: 'transaction' — Mongoose will reject all those activity saves with a validation error, silently swallowed by the catch (_) {} wrapper in every controller. Transaction activity is never persisted.
generatedReport
templateType		 correctness No enum constraint: { type: String, default: 'property_summary' }. The equivalent field on ReportTemplate has a 6-value enum. The controller passes templateType from req.body without validation — any string is persisted.
generatedReport
reportDate		 correctness Typed as String, not Date: { type: String, default: '' }. Date sorting and range queries are impossible. sentAt on the same model is correctly typed as Date.

Model · FieldTypeIssue
message
senderId receiverId listingId		 correctness Typed as String, not ObjectId. No ref declarations. .populate() is impossible; the controller compensates with a manual User.find() query. listingId defaults to '' (empty string) rather than null, making $ne: null / $exists queries unreliable.
listing
propertyCategory ↔ PropertyType.category		 correctness Enum mismatch. Listing.propertyCategory allows 'unknown' but not 'industrial' or 'other'. PropertyType.category allows 'industrial' and 'other' but not 'unknown'. Listings with a PropertyType in category 'industrial' cannot store the matching propertyCategory.
transaction
dealRef		 correctness Missing ref: { type: ObjectId, default: null }. Cannot .populate('dealRef'). The field links to a deal subdocument inside Client.deals — populate across embedded arrays needs the parent model ref, but this is still a documentation/tooling gap.
client (dealSchema)
stageHistory[].stage		 security No enum on the embedded stage history entry. The parent stage field has a 12-value enum, but history entries accept any string — typos and arbitrary values are silently persisted.
buyerRequirement
propertyType		 correctness Field name is semantically wrong. Enum is ['sale', 'rent'] — this is transaction/listing type, not property type. The schema already has a separate propertyTypeInterest field for property category. The matchesProperty() method compares this against Listing.type (which has no enum), creating a silent match-all risk if listing type is ever outside ['sale', 'rent'].
owner
email		 correctness No unique: true and no format validation. Two owner records with the same email are silently permitted. No match regex (unlike BuyerRequirement.buyerEmail which validates format).
owner
active + isDeleted		 correctness Two redundant soft-disable signals with no enforced relationship. A record can have active: true and isDeleted: true simultaneously — no pre-save hook or validation prevents this contradiction.
listing
findByLocation static		 correctness Uses $near / $geometry but location is stored as { lat: Number, lng: Number } — a plain subdocument, not GeoJSON. No 2dsphere index is declared. This static method throws a runtime error on every call.
user
role enum		 correctness Includes undocumented values 'user' and 'buyer' not present in any route guard (requireAdmin, requireRole) or CrmShell access check. CLAUDE.md defines only admin | employee | seller. These roles pass no gate and no page, creating ambiguous access state.
role
getDefaultRoles static		 correctness Seed objects omit createdBy, yet the schema marks it required: true. Running the seed script throws a Mongoose validation error on insert.
document
url		 security URL is constructed from req.protocol + req.get('host') and stored verbatim with no validation or maxlength. A spoofed Host header poisons stored document URLs.
document
mimeType		 security No enum allowlist and no maxlength. Taken directly from file.mimetype (multer reads from the Content-Type header). An attacker can store an arbitrary MIME type string.
reportTemplate
createdBy		 correctness No index: true. All list/update/delete template operations filter by createdBy: req.user.id — every one is a full collection scan.
task
related.kind		 correctness enum: ['client', 'listing', 'none'] — no 'transaction' or 'deal'. Tasks cannot be linked to transactions even though transactions are a first-class entity. Attempting to set related.kind = 'transaction' fails validation.
subscriber
deletedBy		 correctness Soft-delete pattern includes isDeleted + deletedAt but omits deletedBy. Inconsistent with user, role, client, and transaction models which all track who performed the delete.
savedSearch
parsedFilters		 security Mixed type with no size or shape constraint. User-supplied filter objects are persisted as-is. A crafted deeply-nested payload can bloat documents without limit.
securityLog
email		 security Missing index: true. Security logs are routinely queried by email (failed login lookups, audit tools). Every such query is a full collection scan. Also stores plaintext PII with no select: false.
activityLog
compound index		 correctness No compound index on { entityType: 1, entityId: 1, createdAt: -1 }. The dominant query pattern is "all logs for entity X, newest first." Five separate single-field indexes exist but no compound covering this pattern.

Recommended fix order: (1) Add select: false to refreshTokens, loginAttempts, lockedUntil, passwordResetOtpExpires, and taxId. (2) Fix activityLog.entityType enum to include 'transaction', 'listing', 'deal'. (3) Add enum to Listing.type and GeneratedReport.templateType. (4) Fix Message id fields to ObjectId with ref. (5) Fix GeneratedReport.reportDate to Date. (6) Align Listing.propertyCategory ↔ PropertyType.category enums. (7) Add maxlength across all unguarded string fields in bulk.
