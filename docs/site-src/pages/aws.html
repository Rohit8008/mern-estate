What is in deploy/aws

  • nginx.realvista.conf.example: the current single-EC2 server block. SPA fallback try_files $uri $uri/ /index.html, immutable cache for /assets and /fonts, no-cache for index.html, sw.js, workbox-*, manifest, sitemap and robots, websocket proxying for /socket.io, forwarded client IP, security headers. See also Deploy and operate.
  • cloudfront-function.js: viewer-request rewrite so an S3-hosted SPA serves prerendered pages (/privacy, /terms, /cookies, /refunds, /download) and falls back to /index.html for client routes.
  • ecs-task-definition.example.json: Fargate, 0.5 vCPU and 1 GB, secrets by reference, healthcheck on /api/health/live, stopTimeout 30, init process, awslogs.
  • The Dockerfile has an API-only target: docker build --target api. The default target is the full image and is unchanged.

Staged path

  1. Single EC2, hardened. nginx, PM2 or Docker, Atlas. One instance, so the in-process limits are correct.
  2. ECS Fargate, ALB, CloudFront, S3, ElastiCache. SPA in S3 behind CloudFront; /api/*, /socket.io/* and /uploads/* to the ALB; Redis for shared state; Atlas over PrivateLink.
  3. Autoscaling, only once the blockers below are cleared.

Blockers for two or more instances

  • Uploads are on local disk; move them to S3 first (Scaling).
  • Socket.IO has no adapter installed; add the Redis adapter, and use websocket-only transport or sticky sessions.
  • Set the trust-proxy hop count to 2 behind CloudFront plus ALB (1 behind a single nginx). A wrong value makes rate limits and security logs trust a spoofable address.
  • Restrict the ALB security group to the CloudFront origin-facing prefix list and require a secret header from CloudFront.
  • Set REDIS_URL so the rate limiter and cache invalidation are shared.

Alarms

ALB target 5xx and unhealthy hosts, p95 response time, ECS CPU and memory above 80%, running tasks below desired, stopped or OOM tasks, CloudFront 5xx rate, ElastiCache evictions and memory, Atlas connections and lag, error-level log filter, backup freshness (no new object for 26 hours), and a budget alarm.

Database and backups

Stay on Atlas: listing search uses $text and $facet, which DocumentDB does not fully support. Use a PrivateLink endpoint. Back up with Atlas Cloud Backup (M10 and up) plus a scheduled mongodump copied to S3 in another region, and rehearse a restore (Backups).
