Getting started

Install the monorepo, configure the backend and frontend, create your first workspace and admin, and run the tests.

Prerequisites

ToolNotes
Node.js 20CI (.github/workflows/ci.yml) runs on Node 20 and neither package.json declares an engines field. Run the backend on Node 20: on Node 25 the jsonwebtoken dependency chain (jwa / buffer-equal-constant-time) uses the removed SlowBuffer API and crashes on require. The Vite frontend ran fine on Node 25 in our tests.
MongoDBA local mongod is the simplest option. The default MONGO_URI used in docs and the example file is mongodb://127.0.0.1:27017/mern-estate. The unit tests do not need it (they start an in-memory server, see Running tests).
npmEach of backend/, frontend/ and the repo root has its own package.json and lock file.
Redis (optional)Only needed when you run more than one backend instance. See REDIS_URL below.
Cloudinary account (optional)Listing photos and voice notes are uploaded from the browser straight to Cloudinary. Without it the rest of the app works but those uploads do not.

macOS note: mongod --fork is not supported there. Start it in the foreground or via a service, e.g. mongod --config /opt/homebrew/etc/mongod.conf for a Homebrew install.

Clone and install

git clone <repo-url> mern-estate
cd mern-estate/backend  && npm install
cd ../frontend          && npm install
cd ..                   && npm install   # repo root: Playwright e2e only

If npm install fails with a 401 on package fetches, your user-level ~/.npmrc may point at a private registry. Override per command: npm_config_registry=https://registry.npmjs.org npm install.

Backend environment

Copy backend/.env.example to backend/.env. backend/config/environment.js loads it and exits the process if any of these five are missing: JWT_SECRET, REFRESH_SECRET, MONGO_URI, NODE_ENV, MESSAGE_ENCRYPTION_KEY. validateConfig() additionally requires both JWT secrets to be at least 32 characters, and in production requires APP_DOMAIN or DEFAULT_TENANT_SLUG.

Generate secrets with node -e "console.log(require('crypto').randomBytes(64).toString('hex'))" (the example file uses 32 bytes for MESSAGE_ENCRYPTION_KEY).

Run the dev servers

# terminal 1: API on :3000 (nodemon)
cd backend  && npm run dev

# terminal 2: web app on :5173 (Vite)
cd frontend && npm run dev

Check the API is up with curl http://localhost:3000/api/health/health (also npm run health:check from backend/). Open http://localhost:5173.

Create your first workspace and admin

Every record belongs to a workspace (see Multi-tenancy), so a fresh database needs a workspace before anyone can sign in. npm run make-admin alone is not enough on an empty database: it prints "No workspaces exist. Create one first" and stops.

To create the first workspace and its admin, from backend/:

node scripts/provisionTenant.js \
  --name "Acme Realty" --slug acme \
  --admin-email you@example.com \
  --admin-password 'Secret@123' \
  --platform-admin
FlagMeaning
--name, --admin-emailRequired.
--slugWorkspace address; derived from the name if omitted.
--admin-nameUsername for the admin.
--admin-passwordOptional. Omit it and the admin must use "Forgot password" to choose one (recommended for real customers, but needs SMTP).
--plantrial (default), starter, growth or enterprise.
--trial-daysDefault 14.
--no-sample-dataSkip the starter category.
--platform-adminAlso makes this account the vendor-level operator who can administer every workspace (the /platform console). Use for the first workspace only; no tenant-facing API can grant it.

With the dev setup, the sign-in page has a workspace picker. The chosen slug is stored in the browser (localStorage key rv.workspace) and sent as the x-tenant header; leaving it empty means the default workspace, i.e. DEFAULT_TENANT_SLUG (default unless you set it). Easiest local setup: provision with --slug default, or set DEFAULT_TENANT_SLUG=acme in backend/.env. Once a session is issued it carries its own workspace and the server trusts that over the header.

Promoting someone to admin

To promote an existing user, or create an admin inside an existing workspace:

cd backend
npm run make-admin -- --email you@example.com [--username name] [--password 'Pass@123'] [--reset-password] [--workspace acme]

The default password when none is given is ChangeMe@123, printed to the console. --workspace is optional when exactly one workspace exists and required when there are several. An existing user is promoted to admin; their password only changes if you pass --reset-password.

Seed data

Command (from backend/)Effect
npm run db:seed-demoRealistic sample data for demos. Upserts by key, safe to re-run. Needs an existing admin user (it tells you to run make-admin otherwise).
npm run db:seed-freshDestructive, no confirmation. Wipes the collections of the workspace it runs in and inserts clean sample data. Keeps the first admin and creates a demo employee and seller.
npm run db:seed-categoriesSeeds categories with their dynamic fields.
npm run db:seed-rolesSeeds the default roles (the first is "Super Admin", with all permissions). See Team, roles and permissions.

Seed and purge scripts act inside one workspace. When several workspaces exist the bootstrap refuses to guess and asks for --workspace <slug>. Read the script header before running anything against a database holding real data.

Running tests and lint

# backend (Jest; starts mongodb-memory-server, so no local Mongo needed)
cd backend
npm run test           # also: test:watch, test:coverage, test:ci
npm run lint           # npx eslint@8 .   (lint:fix to autofix)
npm run format         # Prettier, backend only

# frontend (Vitest)
cd frontend
npm run test           # vitest --run
npm run test:ui        # Vitest UI
npm run test:coverage
npm run lint           # eslint src --ext js,jsx

The backend suite registers the tenancy plugin before any model loads (tests/setup.js) and runs every test as a default test tenant, so isolation is exercised for real. Several tests act as guard rails: routeAccess.test.js fails if a mounted route is neither guarded nor allowlisted, validationCoverage.test.js fails a write route without validateBody, and permissionCatalogue.test.js fails on an unknown permission key. At the repo root, npm run e2e runs the Playwright suite.

Project conventions

CLAUDE.md at the repo root is the contributor rulebook and is worth reading in full before your first change. The rules that bite newcomers most:

  • Never write a tenantId filter by hand and never add a bare unique: true; uniqueness is {tenantId, field}. Scripts must enter a workspace via bootstrapScript() from scripts/_bootstrap.js and must not import models directly.
  • Every POST/PUT/PATCH needs validateBody(schema); stripUnknown silently drops fields the schema omits.
  • Every route is guarded or listed in backend/security/publicRoutes.js with a reason.
  • Frontend: use apiClient from @/utils/http, never raw fetch; icons come from react-icons/hi; never hardcode currency or area units (use utils/currency.js); use literal Tailwind class names, never interpolated ones.
  • User text never goes into a regex raw: use utils/escapeRegex.js.
  • Notifications go through utils/notify.js, not sendMail from a controller.

Troubleshooting

SymptomCause and fix
Backend prints "Missing required environment variables" and exitsOne of the five required variables is unset, including NODE_ENV and MESSAGE_ENCRYPTION_KEY.
"Configuration validation failed" about a secretJWT_SECRET or REFRESH_SECRET is shorter than 32 characters.
Crash on require in jwa / buffer-equal-constant-timeNode too new (SlowBuffer removed). Use Node 20 for the backend.
Server cannot connect to MongoCheck MONGO_URI and that mongod is listening (lsof -nP -iTCP:27017 -sTCP:LISTEN). A cloud cluster whose DNS no longer resolves fails the same way.
Every API call fails or sign-in finds no oneA query with no workspace throws by design. Provision a workspace, then either pick it in the sign-in workspace picker or set DEFAULT_TENANT_SLUG to its slug.
Browser shows CORS errors from a non-default originIn development only localhost:5173 and localhost:3000 are allowed; add others to EXTRA_CORS_ORIGINS. In production set FRONTEND_URL.
All writes fail with CSRF_TOKEN_INVALIDEvery write must carry X-CSRF-Token; use apiClient, which handles it, and make sure a custom proxy forwards that header.
Rate-limited while testingAuth routes allow 20 requests per 15 minutes by default (AUTH_RATE_LIMIT_MAX). Raise it locally or set ENABLE_RATE_LIMITING=false.
Photo upload failsSet both VITE_CLOUDINARY_* variables and restart Vite; they are read at build/start time.
Records created by a script are invisible in the appThe script imported a model before the tenancy plugin registered. Use bootstrapScript().
Cannot create a second user without a phone numberA stale phone_1 index from before the partial-unique phone_unique_string index. Drop it (db.users.dropIndex('phone_1')) or run User.syncIndexes() once.
