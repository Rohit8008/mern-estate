Frontend

The React single-page app: routing and shells, the design system, state, API access, i18n and locale, printing, and the SEO build.

Stack and layout

React 18, Vite 4, Tailwind 3.3, react-router-dom 6, Redux Toolkit with redux-persist, i18next, Leaflet for maps, ApexCharts for charts, socket.io-client for realtime. Source lives in frontend/src:

FolderWhat is in it
app/AppRoutes.jsx (the authoritative route list), AppShell.jsx, CrmShell.jsx, screenRegistry.js, commands.js (the shared command list), RouteSeo.jsx, keyboard shortcuts.
pages/One file per screen. Most are lazy-loaded from AppRoutes.jsx.
components/Feature components (panels in Settings, GlobalSearch, crm/*).
design-system/Shared primitives, imported from the barrel '../design-system'.

i18n/i18next setup and locales/*.json.
redux/Store and the user slice; only user is persisted.

Routing and shells

Two layouts. AppShell wraps public and seller routes with a minimal header. CrmShell wraps every CRM route with the sidebar and top bar and requires role === 'admin' || role === 'employee'. Guards are AdminRoute, SellerRoute, PrivateRoute and the canAccess check in CrmShell.

Read frontend/src/app/AppRoutes.jsx rather than any list in prose. Renamed paths keep aliases: /contacts to /owners, /deals to /pipeline, /buyer-requirements to /buyers, /client-reports to /reports.

Reachable without a session: /, the legal pages, /download, /sign-in, /forgot-password, /s/:token (a share link), /invite/:token and /unsubscribe/:token. The property book is not browsable anonymously.

The sidebar is data, not markup

The server owns what each screen is (backend/tenancy/screenCatalogue.js: id, label, section, permission). The client owns how it looks (app/screenRegistry.js: icon, route). hooks/useScreens.js intersects both with the workspace's feature flags and the user's permissions.

Screen ids are a contract with every workspace's stored settings. Renaming one detaches the screen from the catalogue and it vanishes from the menu with no error. Add and deprecate freely; never rename. A workspace's own rename of a screen beats a translation (useScreens compares label to defaultLabel).

Adding a screen: an entry in both files plus a route in AppRoutes.jsx.

Command palette and shortcuts

The ⌘K palette and the keyboard shortcuts read one list, app/commands.js (useCommands), filtered by screens and permissions. Add an action there, never in either consumer. A "New …" command links to ?new=1 and the destination page opens its own create form.

Talking to the API

Always use apiClient from @/utils/http; never raw fetch.

import { apiClient, normalizeImageUrl } from '@/utils/http';

await apiClient.get('/endpoint');
await apiClient.post('/endpoint', data);
await apiClient.patch('/endpoint', data);
await apiClient.delete('/endpoint');
await apiClient.upload('/endpoint', formData);   // multipart
  • Sessions are httpOnly cookies. A 401 triggers one refresh and a retry (fetchWithRefresh); see Authentication.
  • Failures arrive as one envelope with a code. Branch on code; show message to people (Request pipeline).
  • Pass { silent: true } to suppress the global error toast when the caller handles the failure itself (a widget that should degrade quietly).
  • Run image URLs through normalizeImageUrl(); it turns absolute localhost URLs into relative paths so production works.
  • Uploads of images and voice notes go straight to Cloudinary from the browser (utils/cloudinary.js, unsigned preset; audio uses the video resource type). Only documents go through /api/documents.

Design system

Import from the barrel: import { Button, Modal, Table } from '../design-system'. Components: Avatar, Badge, Button, Card, ColumnToggle, Drawer, Dropdown, EmptyState, Input/Select/Textarea, KpiCard, Modal, PageHeader, Pagination, SearchBar, Skeleton, Spinner, Table, Tabs, Toggle (Switch/Checkbox), Toolbar, Tooltip. Modal and Drawer share useDialog.

  • Icons: react-icons/hi (HeroIcons) only. No Font Awesome, no lucide, no emoji icons.
  • Maps: Leaflet occupies z-index 400–800. On map pages use inline confirmation (a rose-50 strip with Cancel and Delete, see PropertyDocuments.jsx) instead of a modal; elsewhere use ConfirmDialog.
  • Tokens: new code should prefer theme tokens (bg-card, border-border, text-foreground, text-muted-foreground, bg-secondary, hover:bg-accent) over slate classes, so dark mode needs no override entry.

Colour

The accent is a deep petrol blue on an OKLCH ramp named brand in tailwind.config.js. The same config overrides Tailwind's stock indigo with that ramp, so the ~520 older indigo-* classes repaint coherently and the dark-mode override sheet in index.css keeps working. Use brand-* in new code; do not introduce new indigo-*.

Interpolated class names never work. `text-${color}-400` is not emitted because Tailwind scans source as plain text. Every colour must appear as a complete literal string, usually via a lookup table keyed by variant.

Per-workspace branding uses CSS variables on :root and utilities such as bg-workspace. text-balance and text-pretty are hand-defined in index.css (Tailwind 3.3 predates the built-ins).

Lists

A list page sorts and pages on the server: <Th sortKey sort onSort> sets the sort, the page sends sort=key:asc|desc&page=&limit=, and <Pagination> reads total from the response. Sorting one page of results sorts the wrong set; useTableSort's sorted is only for lists that are already whole. Use Skeleton/SkeletonRows for loading, EmptyState for empty, and ColumnToggle with useColumnPrefs for column choice.

Forms that matter

  • Listing form: pages/ListingForm.jsx with mode="create"|"edit" is the only listing form; CreateListing and UpdateListing are tiny wrappers. A new property field is one edit in EMPTY (hooks/useListingForm.js) plus one input. If it aliases a native column, update NATIVE_FIELD_ALIASES in both frontend/src/utils/nativeFieldAliases.js and backend/utils/importMapping.js.
  • Edit conflicts: listing and client edits send expectedUpdatedAt. A 409 VERSION_CONFLICT shows EditConflictNotice inline with "Load their version" or "Keep mine".
  • Category fields: utils/categoryFieldRules.js mirrors the cheap server rules for inline hints; the server (backend/utils/categoryFields.js) is authoritative.

Locale, currency and translation

utils/currency.js holds every formatter. TenantProvider pushes the workspace locale in with setLocaleConfig(). Use formatCurrency, formatNumber, formatDate, formatArea and areaUnitLabel.

Never construct Intl.NumberFormat at a call site and never hardcode ₹, en-IN or sq ft. All six area units must work: sqft, sqyard, sqm, acre, cent, guntha. A two-way ternary once showed "sq yard" for the other four.

Translations are src/i18n/locales/*.json, discovered by a Vite glob, so a new language is one dropped-in file (en and hi ship today). i18n/__tests__/locales.test.js fails the build on a missing key or a dropped {{placeholder}}, and keys-exist fails on a t('key') that is absent from en.json. Some newer panels use plain English strings; both are accepted by the tests.

Realtime

config/socket.js connects to VITE_SOCKET_URL for messages, presence and notifications; the unread count comes from useUnreadCount and NotificationFeedProvider.

Printing

.print-area, .no-print, .print-only and .print-stack in index.css are the convention. Use <PrintButton /> rather than per-page print CSS; browsers already offer "Save as PDF".

SEO

Only a handful of pages are public, and they are the only ones meant to be indexed. The list lives in frontend/seo/pages.mjs and is read by the build and the runtime.

  • Build (seo/vite-plugin-seo.mjs): writes a real HTML file per public page with its own title, description, canonical, Open Graph and Twitter tags, JSON-LD and a no-JavaScript fallback; generates sitemap.xml and robots.txt using VITE_SITE_URL. The home page also carries FAQPage data drawn from landing.faq in en.json.
  • Runtime (app/RouteSeo.jsx): after client-side navigation, sets robots, canonical and social tags for public pages and noindex, nofollow for every other route, so a route missing from the list fails closed.
  • Static assets: public/og-image.png (1200×630). There is no hand-written robots.txt; the build produces it.

The web server must fall back with try_files $uri $uri/ /index.html so /privacy serves privacy/index.html. See Deploy and operate.

Marketing-claims policy

Public pages (Home, Footer, MinimalHeader, Legal) carry no performance statistics, no customer counts and no attributed testimonials. Every claim must be traceable to something in the repository or to a measurement someone can produce. Legal text changes in the same commit as the behaviour it describes, and LEGAL_UPDATED (pages/Legal.jsx) moves with LEGAL_VERSION (backend/utils/legalVersion.js). Business identity lives only in BUSINESS in utils/marketingCopy.js; null fields are not printed, so never fill one with a guess.
