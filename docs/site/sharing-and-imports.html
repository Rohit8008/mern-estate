Sharing and imports

Send a shortlist to someone without an account, bring properties and leads in from spreadsheets, and export or erase a person's data.

Share links

Nothing about a listing is reachable without a session, so a share link is the only way a property leaves the agency. An agent picks properties, gets a link and sends it (for example on WhatsApp). The recipient opens /s/:token with no account.

The token is the credential. Anyone holding the link can open it until it expires or is withdrawn. Treat a link like a password: send it only to the intended person, prefer an expiry, and add a passcode for anything sensitive.

Create a link

To share: on All Properties select one or more rows and choose Share, or use Share on a single property's page. Fill in:

FieldBehaviour
What is this list?A label so your list of links is readable (up to 120 characters).
Sent to, their phoneA note to yourself. Never shown on the shared page.
MessageUp to 1,000 characters, shown at the top of the shared page.
Link expires in7, 30 (default), 90 days or No expiry. The API accepts 1 to 365 days; null means no expiry and is a deliberate choice.
PasscodeOptional, at least 4 characters. Stored hashed (bcrypt). The recipient is asked for it before anything is returned.
Show the priceOn by default. Off withholds price, offer price and the offer flag from the page, for gauging interest before a number is agreed.
  • A link carries between 1 and 50 properties.
  • The token is 32 random bytes (base64url), so it cannot be guessed.
  • You cannot share what you cannot see. The server re-reads the chosen properties through your own access scope (listingScope). If any are outside it, the whole request is refused with "Some of those properties are not yours to share". An employee can share only listings they created, are assigned to, or that sit in their assigned categories; sellers only their own. There is no separate permission key for sharing; any signed-in user passes this check for properties in scope.

Track and revoke

The Share links dialog on All Properties lists links with their state, view count and last-viewed time. An admin sees every link in the workspace (latest 200); anyone else sees their own. To withdraw a link: Revoke. It sets revokedAt and revokedBy instead of deleting, so "who did we send this to and when did we stop it" stays answerable. Only the creator or an admin can revoke, and a link already withdrawn cannot be revoked again. Every successful open increments the view count; a count that climbs unexpectedly means the link has spread.

What the recipient sees

GET /api/share/open/:token is the one unauthenticated endpoint that returns property data. It is rate-limited to 60 requests per 15 minutes. The workspace comes from the share record, so a token reaches only the workspace that issued it.

The page shows only: name, description, address, area name, locality, city, state, type, status, bedrooms, bathrooms, area (sq ft), sq yard, plot size, furnished, parking, photos, map location and, unless hidden, regular price, offer price and the offer flag. The page is dressed in the agency's name, logo, brand colours and support email and phone.

Imports: shared rules

Both importers (properties and leads) follow the same pattern:

Choose file
→
Match columns
→
Preview (writes nothing)
→
Commit in batches
  • Every row is validated before anything is written. Preview and commit build rows through the same code, so the report you approve is what lands.
  • Rows are written in batches with per-row results, so one bad row costs that row and not the file. Row problems are returned individually and capped (see each importer).
  • Files: .xlsx, .xls or .csv, up to 15 MB (the browser rejects larger files and unsupported types before upload).
  • Monthly import meter. The plan limit maxImportRowsPerMonth counts rows brought in by either importer (trial 2,000, starter 20,000, growth 100,000, enterprise unlimited). Rows are reserved before writing and the unused part is released, so rejected rows cost nothing. If the file would pass the cap the request answers 402 with details.limit, used, requested and remaining. The counter resets at the start of each month in the workspace's timezone (a daily job rolls it).

Import properties

To import: Import from Excel in the sidebar, the Import button on Categories, or /admin/import. Admin only (the screen is adminOnly and every route is requireAdmin); it is a screen a workspace can switch off.

  1. Choose file. Pick the category first: its fields decide what columns are understood. Download a template CSV for that category (GET /api/listing/import/template) to skip the mapping step entirely.
  2. Match columns. Headers are auto-mapped using synonyms (for example "plot no", "unit number" and "khasra no" map to Property / plot no.; "bhk" to Bedrooms; "gaj" to sq. yard). Each column can be sent to a core field, a category field or ignored. Prices accept forms like "1.4 Cr".
  3. Review. Preview classifies each row as ready, error, duplicate (already in the system) or duplicate_in_file (an earlier row in the same file is the same property). Pick what to do with existing duplicates:
    • Leave the existing one alone (skip, default; safest for topping up a list);
    • Update it with this row (update; overwrites the existing property);
    • Add it anyway (create; a second record).
  4. Done. A summary with created, updated and skipped rows. You can download "problems" and "not imported" CSVs.

Rules to know:

  • A property's identity is its propertyNo within the category when present, otherwise name plus address plus city (case and whitespace ignored).
  • Required: name and address (the bulk endpoint refuses rows without both). The CSV chunk limit is 500 rows per request, and the server reports a total of 20,000 per job; the browser sends bigger files in chunks and reconciles duplicates across chunks.
  • The plan limit maxListings is checked against the number of rows about to be created before any row is written, so a file never half-imports past the cap. Updates do not add listings but do count against the monthly import meter.
  • Native field aliases. A column mapped to a category field whose key is sqYard, rateSqYard, totalValue, propertyNo, plotSize, remarks or areaName is stored in the real column rather than in attributes. A value that cannot be read (for example text in a number column) is left blank with a warning rather than failing the row. Latitude and longitude columns collapse into the location pin and are ignored if out of range.
  • Imported listings are owned by the admin who ran the import (userRef); updating an existing one never reassigns its creator.

Import leads

To import portal enquiries (99acres, MagicBricks, Housing and similar exports): palette command Import leads or /admin/import-leads (the page sits under the admin routes). The API needs createClient.

  1. Upload the file (.csv, .xlsx, .xls; 15 MB).
  2. Map columns. Fields: Name (required), Phone (required), Email, Alternate phone, Source, Requirement, Property type, Preferred locations, Budget (min), Budget (max), Enquiry date.
  3. Review. Rows are new, duplicate or error. Choose a default source for rows without one (otherwise "Import"); the list of workspace lead sources feeds this picker.
  4. Done. Shows created and skipped counts.
  • Up to 5,000 rows per request.
  • Duplicates are skipped, never merged, because deciding two records are the same person is a judgement. A row is a duplicate if its ten-digit phone key, or (for a short number) its email, or (no email) the short number together with the name, already exists or appeared earlier in the same file.
  • Leads are assigned using the workspace's lead-assignment rule, dealt out for the whole batch at once, so a 400-row import is not all owned by whoever pressed the button (see Assignment rules). New leads start with status lead, are scored on the way in, and honour the email suppression list.
  • New source names in the file are added to the lead sources catalogue (at most 25 per import) so the ROI report can see them.
  • The response is a summary: created, skipped (duplicates, errors), inputCount, inserted, updated (always 0), failed, writeFailures and rowErrors, each with a row number, code (INVALID_ROW, VALIDATION_FAILED, DUPLICATE, WRITE_FAILED) and message. rowErrors is capped at 200; rowErrorsTruncated says the list was cut while the counts stay exact.
  • Up to 50 lead.created webhook events are emitted per import, not one per row.

Data export and erasure (data rights)

These cover access and erasure requests from a person. The admin UI is Settings, System, Data requests.

ActionEndpointWho
Export my own dataGET /api/data-rights/export/meany signed-in user
Export a team memberGET /api/data-rights/export/user/:idexportData
Export a contact (client, owner or buyer)GET /api/data-rights/export/:kind/:idexportData
Erase a team memberDELETE /api/data-rights/erase/user/:idadmin only
Erase a contactDELETE /api/data-rights/erase/:kind/:idadmin only
  • An export is a JSON download. A user export contains their account (without password or refresh tokens), the clients, owners, buyer requirements, tasks, documents (no file path), notifications and message metadata (not message bodies) linked to them, plus activity and security logs. A contact export contains the record, its documents and its activity.
  • Every export is written to the activity log (data.exported).
  • Erasing a team member closes the account, ends every session, replaces username and email with "Former team member <id>" and a .invalid address, and clears name, phone, avatar and address fields. The records they created stay, now attributed to the anonymised account, so the agency's audit trail remains intact. You cannot erase your own account (ask another admin) or a platform operator.
  • Erasing a contact removes the personal details outright (name becomes "Erased contact"; email, phone, notes, requirements, communications, follow-ups and photos are cleared) and keeps only the anonymous shape needed for reporting totals. It is not reversible.

Exporting or erasing does not narrow to the requester's own leads: a contact export is authorised by exportData alone, not by lead ownership. Grant exportData only to people who should see every contact.
