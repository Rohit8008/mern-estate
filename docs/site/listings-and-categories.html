Listings and categories

Adding and finding properties, how categories define extra fields, how paperwork and voice notes attach, and how search and maps behave.

The property book

A listing is one property. Properties are grouped into categories (a colony, a project, "Apartments"), and a category decides which extra fields a property in it collects. The register is the All Properties screen (/properties); the form is /create-listing and /update-listing/:listingId. Nothing about a listing, category or property type is reachable without a signed-in session; to show a property to someone outside the agency use a share link, see Sharing and imports.

Add or edit a property

To add a property: sidebar, Add Property (needs createListing; employees with no custom role may also create, subject to category assignment). To edit: open the property and choose edit. Both use the same form (pages/ListingForm.jsx); the only difference is that Documents and Voice notes appear only once the property exists.

A listing's status also changes by itself: when a deal is marked Won on a lead, the linked listing becomes sold (or rented for a rent or lease deal). See Deals.

Things the form does for you

  • Unsaved changes are tracked against what was loaded.
  • Edit conflicts. The form remembers the updatedAt it loaded and sends it back as expectedUpdatedAt. If a colleague saved first the server answers 409 VERSION_CONFLICT and the form shows a notice with Load their version or Keep mine (which resends without the guard). A caller that sends no version (scripts, the mobile app) gets last-write-wins.
  • Find on map fills only empty fields, so a typed address is not overwritten by the geocoder's best match, but the map pin itself is always updated.
  • Category fields whose key is a real column (bedrooms, bathrooms, parking, furnishing) are copied into that column too, because filters, cards and the bed/bath line read the column.

What gates it

  • Plan limit maxListings (trial 250, starter 2,500, growth 25,000, enterprise unlimited). Creating over the cap answers 402. Bulk import checks the number it is about to create before writing any row.
  • Employees can create a listing only in a category assigned to them (otherwise "Not allowed for this category"), and can edit or delete only listings they created, are assigned to, or that sit in their assigned categories. Sellers see only their own listings. See employee scoping.
  • Buyers cannot create, update or delete listings.
  • A workspace rule can normalise or veto a save (for example refuse to save without a price); the user sees the rule's message.

Deleting and restoring

Deleting a listing is always a soft delete (isDeleted, deletedAt). Removing a property from the board hides it from search, facets and lists but does not destroy it.

  • To delete: from the board or the property. Anyone who can access the listing can delete it through DELETE /api/listing/delete/:id; admins also have POST /api/listing/soft-delete/:id.
  • To restore: admin only. On All Properties open the bin (the Deleted listings dialog) and restore; it lists up to 200, newest deleted first. Restoring counts against the plan's maxListings like a new property and answers 402 when the workspace is full.

Restoring does not re-check the plan's maxListings cap; the cap is enforced when listings are created or imported, not when they are un-deleted.

The All Properties board

The same data in four views, chosen with ?view= in the URL: Main table (default), Pipeline (by status), Cards and Map. The table sorts and pages on the server. Filters, all kept in the URL so a view is linkable: search text, status, assigned agent, owner, city, locality, listing type, category, property category, property type, min and max price, minimum bedrooms and bathrooms, furnished, parking and offer.

  • Saved views (the bar above the table) store the current filter query string under a name. They belong to the signed-in user, follow them across devices (/api/user/saved-views/:namespace), and hold up to 50 per list. Views saved by older versions in the browser are merged up once.
  • Assigning an agent to a listing is admin-only (POST /api/listing/assign-agent and /unassign-agent). The assigned agent gains edit access, and "My assigned" lists their listings.

Search

There is one listing search, backend/search/listingSearch.js, used by the board, the search page and the command palette. It scopes results to what the signed-in user may see, then matches in tiers and stops once there are enough results:

  1. Identifier: property number, pincode or id, exact.
  2. Text: the database text index, ranked by relevance.
  3. Prefix: an anchored prefix on city, locality, area name or name ("Sush" finds "Sushant").
  4. Fuzzy: a looser pattern, only against a set the filters have already narrowed.

Ranking and paging happen in the database, so the total is the real number of matches and any page can be fetched.

Facet counts. GET /api/listing/facets returns counts by status, category, city, locality, type and assigned agent (top 50 for the open-ended ones) plus total count, total value and average price over the whole filtered set. Use it for any header count; never count a page.

The command palette (⌘K)

Press ⌘K on macOS or Ctrl K elsewhere. The palette searches listings, clients, owners, buyers, tasks and users in parallel, each applying its own access rules, and understands natural phrases such as "3 BHK in Gurgaon under 2cr" or "leads assigned to Amit this month". It also lists actions (a "New …" command opens that page's create form via ?new=1) and recently visited pages, filtered by your screens and permissions.

  • Save this search (the save control that appears once you have typed two characters) names a query. Saved searches are per user; pin toggles a search to the top (pinned first, then most recently run); delete is a soft delete (/api/search/saved).
  • Clicks on results are recorded. Admins can see what the team searches for under Settings, System, Search insights (GET /api/search/analytics, admin only).

Destructive actions answer 409 with a count

  • Deleting a category in use answers 409 with details.listingCount. The UI turns that into a choice: See the properties, Keep it, or Delete anyway, which resends with ?force=true. Listings keep pointing at the slug, so their category fields stop rendering until the category is restored. Delete is soft.
  • Removing a field that holds values answers 409 with details.removedWithData (field and number of properties). Confirming resends with ?force=true. The values stay in the database but nothing displays them.

Field definition rules

A category's fields govern how every listing in it is stored, so they are validated structure (backend/utils/categoryFields.js is authoritative; frontend/src/utils/categoryFieldRules.js mirrors the cheap rules as inline hints).

  • At most 100 fields per category.
  • Key: starts with a lowercase letter, then letters, digits or underscores, up to 40 characters; unique within the category.
  • Type: text, number, boolean, select, date, textarea.
  • Label required, up to 100 characters.
  • Select needs at least one option, at most 200, no duplicates.
  • Min / max must be numbers with min not above max.
  • Pattern (regex) up to 200 characters, must parse, and nested repetition such as (a+)+ or (a|a)* is rejected because it can hang the process.
  • Show when: a field can depend on another field's value; it cannot depend on itself and the target must exist.
  • Other per-field settings: required, description (300), placeholder (200), default value, multiple (for select), unit (30), group (60). Order is the order you send them.

Reserved keys

A key may not shadow a real listing column or prototype name. Reserved: __proto__, constructor, prototype, toString, valueOf, hasOwnProperty, _id, id, name, description, address, city, locality, state, pincode, type, status, category, attributes, location, regularPrice, discountPrice, offer, parking, furnished, bedrooms, bathrooms, imageUrls, ownerIds, userRef, assignedAgent, tenantId, isDeleted, deletedAt, createdAt, updatedAt, __v, propertyType, propertyCategory, commercialType, plotType.

Category paperwork and photos

A category (colony) carries typed documents. Upload them on the category (kind category, needs uploadFiles; employees only for categories assigned to them). Types (backend/utils/documentTypes.js):

  • The type is checked against the file's detected content, not the name or declared type. Allowed files: PDF, Office documents, JPG and PNG, up to 10 MB. A file that fails is refused with a message.
  • isPublic defaults to false and is never set implicitly. The upload form pre-ticks it for the types marked yes ("suggest public"), but the server never applies that. Only an admin can publish; an employee asking for isPublic gets 403. Documents also count against the plan's storage limit (maxStorageMb).
  • "Public" here means published to the category's page for signed-in members (GET /api/documents/public/category/:categoryId returns only published documents, without the uploader's name). The route sits behind a session; a share link is how it reaches someone outside the agency. The comment above the controller still says it is reachable without signing in; the route registration is what governs.
  • Documents can also be attached to a single property (edit mode, Documents section; you must have created it or be assigned to it unless you are an admin), to a client, deal or transaction. A lead's Documents tab uses the same store.

Public category reads (publicView()) never include defaultLocation, soft-delete metadata or tenantId.

Voice notes

On a property in edit mode, the Voice notes section records audio in the browser (microphone permission required). The recording is uploaded to Cloudinary (audio uses its video resource type) and the resulting URL, a label and the duration in seconds are saved on the listing (POST /api/listing/:id/voice-notes). Anyone who can edit the listing may add or delete a note. The backend also has POST /api/upload/audio for direct uploads: it validates the real file type (webm, ogg, m4a, mp3, wav), allows up to 25 MB, and counts against storage. Voice notes are among the internal fields returned only to admins and employees.

Maps and geocoding

Maps use Leaflet. The address lookup (GET /api/geocode/search, /reverse; sign-in required) proxies OpenStreetMap's Nominatim service and caches results in memory for one hour (500 entries). A listing's pin is stored as location.lat and location.lng; the Map view of the board shows listings with a location. Leaflet panes use z-index 400 to 800, so pages with maps use inline delete confirmations instead of modals, and the listing form's sticky save bar sits at z-index 900.
