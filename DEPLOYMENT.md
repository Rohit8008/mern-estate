# Deploying to Render

The full operations guide (environment variables, health checks, backups, scaling, nginx and Docker alternatives) is in the docs site: [`docs/site/operations.html`](docs/site/operations.html). This file is the short Render path, matching [`render.yaml`](render.yaml).

## What the blueprint creates

| Service | Type | Notes |
|---|---|---|
| `mern-estate-api` | Node web service | `cd backend && node index.js`, health check `/api/health/startup`, port 10000 |
| `mern-estate-client` | Static site | `cd frontend && npm run build`, serves `frontend/dist`, rewrites `/api/*` and `/uploads/*` to the API, SPA fallback to `/index.html` |

## Before you deploy

- **Node 20 or newer** (`engines` in `package.json`).
- **MongoDB**: Atlas or self-hosted. For Atlas, allow Render's egress IPs (or `0.0.0.0/0` if you accept that).
- **Cloudinary** account and an *unsigned* upload preset. Images and voice notes upload from the browser; there is no Firebase.
- Optional: an SMTP account (invitations, password-reset OTP and workflow mail), Twilio (SMS), Redis (shared cache and rate limits), an OpenObserve instance (log shipping).

## Steps

1. Push the repository to GitHub and create a Render **Blueprint** from it. Render reads `render.yaml`.
2. Set the variables marked `sync: false` in the dashboard.

   **API (`mern-estate-api`)**

   | Variable | Value |
   |---|---|
   | `MONGO_URI` | Your connection string. Required. |
   | `FRONTEND_URL` | The client's public origin **with scheme**, e.g. `https://mern-estate-client.onrender.com`. CORS compares origins exactly. |
   | `DEFAULT_TENANT_SLUG` or `APP_DOMAIN` | Production refuses to boot without one. `DEFAULT_TENANT_SLUG` serves a single workspace; `APP_DOMAIN` enables `<workspace>.<domain>` routing. |
   | `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM` | Email. Without SMTP the app shows invite links instead of sending them. |
   | `REDIS_URL` | Optional. Required before running more than one API instance. |
   | `OPENOBSERVE_URL`, `OPENOBSERVE_USERNAME`, `OPENOBSERVE_PASSWORD` | Optional. Without them logs go to stdout only. |

   `JWT_SECRET`, `REFRESH_SECRET` and `MESSAGE_ENCRYPTION_KEY` are generated by Render on first deploy. **Never rotate `MESSAGE_ENCRYPTION_KEY`**: existing encrypted messages and stored SMTP passwords depend on it. Rotating the JWT secrets signs everyone out.

   **Client (`mern-estate-client`)**

   | Variable | Value |
   |---|---|
   | `VITE_CLOUDINARY_CLOUD_NAME`, `VITE_CLOUDINARY_UPLOAD_PRESET` | Uploads |
   | `VITE_API_RESPONSE_SECRET` | Response decryption (only matters if the API sets `ENCRYPT_API_RESPONSES`) |
   | `VITE_SOCKET_URL` | The API's origin, for Socket.IO |
   | `VITE_SITE_URL` | Optional. Public origin used in `sitemap.xml`, canonical URLs and social tags (default `https://realvista.duckdns.org`) |

   `VITE_*` values are baked in at build time, so changing one needs a rebuild.
3. Update the destination in the client's `/api/*` and `/uploads/*` rewrites if your API service is not named `mern-estate-api`.
4. Create the first workspace and operator once the API is up (Render shell):

   ```bash
   cd backend
   node scripts/provisionTenant.js --help        # workspace + first admin; --platform-admin for the first vendor operator
   ```

## After deploy

- `GET /api/health/live` should answer; `/api/health/ready` also checks the database.
- Keep the API at **one instance** until a Socket.IO Redis adapter is added: presence is held in-process.
- Back up the database before upgrades: `cd backend && npm run db:backup`. Restores are destructive and prompt for confirmation (`npm run db:restore -- --list`).
- Databases created before the user-token TTL fix need a one-time `db.users.dropIndex('refreshTokens.createdAt_1')`; see the Operations page.

## Troubleshooting

| Symptom | Likely cause |
|---|---|
| API exits at boot | A required variable is missing: `NODE_ENV`, `MONGO_URI`, `JWT_SECRET`, `REFRESH_SECRET`, `MESSAGE_ENCRYPTION_KEY`, and `DEFAULT_TENANT_SLUG` or `APP_DOMAIN` in production |
| Browser shows CORS errors | `FRONTEND_URL` lacks the scheme or does not match the client origin exactly |
| Sign-in answers `WORKSPACE_NOT_FOUND` | The workspace slug does not exist, or `DEFAULT_TENANT_SLUG` is wrong |
| Realtime not updating | `VITE_SOCKET_URL` unset or wrong; rebuild the client after changing it |
| Pages like `/privacy` 404 | The host is not falling back to `index.html` / the per-page HTML in `dist` |
